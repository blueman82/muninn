Muninn · automatic learning

A default policy that stays bound to the local machine

The repository supplies the policy values. The installer binds them to a real Codex executable and the local Muninn store. Prompt recall settings remain a separate choice.

First install or first activation

1

Clone carries the profile

tools/default_codex_policy.json stores the editable limits and approval record.

2

Installer checks the host

It requires Apple silicon macOS, a signed codex CLI on PATH, and a canonical Codex sign-in directory.

3

Muninn binds local facts

After the store exists, Muninn writes private capability files bound to the host, data directory and executable.

4

Policy and admission commit

After provider setup succeeds, Muninn records the policy and source boundary in one activation transaction.

Default-home install or unconfigured store

On a supported host, the default profile is frozen, locally bound and activated after setup.

Already configured store

Custom policies, used defaults and disabled admission stay unchanged. An enabled repository default refreshes only with no requests or knowledge and a newer approved profile.

Host checks fail

The install can finish, but learning stays pending. Muninn does not invent an executable capability.

A session ends

Learning path

SessionEnd or PreCompact captures a bounded request. The policy controls whether the runner may review it. A result still passes through Muninn's knowledge admission and commit rules.

Prompt recall path

recall.offrecall.advisoryrecall.on select prompt-time behavior. None of these settings blocks SessionEnd or PreCompact learning.

Provider hook trust is separate. Codex may ask you to trust Muninn's hooks with /hooks.

Limits and their boundary

The default allows two rounds, 1 MiB of input, 32 KiB of output, 12,000 bytes of context, a 120-second deadline, one attempt, one concurrent request and project scope only.

The ongoing policy has no aggregate call limit, cost limit or expiry.

Byte limits bound one request. They do not cap total use or total provider cost.

To customize, edit the profile in your private clone. Refresh preserves host, runner, prompt and budget bindings. It allows smaller limits and the approved v1-to-v2 input increase up to 1 MiB. Any learning request, knowledge entry, custom policy or disabled admission prevents automatic refresh.
