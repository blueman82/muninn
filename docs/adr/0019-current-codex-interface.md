# 0019: Follow the current trusted Codex interface

## Status

Accepted for source implementation, 2026-11-04.
Initial owner activation stays a different affirmative installer decision.
Source `review`, last gate, `delivery`, installation and live `acceptance` are different milestones.

## Context

The file at a recorded executable path can be removed when the Codex manager updates.
Keeping obsolete packages or rewriting policy for each version makes learning depend on a changing software version.
Ignoring a previous grant's hash would silently change what the owner approved.

## Decision

Add an explicit managed interface selection for the owner's fixed local Codex manager on Darwin/arm64.
Resolve `current` only in its canonical `releases` subtree.
Check the complete bounded package and primary Apple signature.
Negotiate necessary advertised arguments with three fixed, isolated model-free probes.

Missing `isolation` refuses.
Package metadata is not whole-package publisher proof.

Keep previous unchanged policy shapes, canonical bytes and fingerprints.
Apply their actual executable hashes.
One initial checked UPDATE RULE changes the runner selection and enrolls this physical computer.
A preview that writes nothing and new yes/y consent are necessary.

Keep each other policy term, account, scope and limit unchanged.

The previous computer digest includes its name.
A different digest does not prove that the physical computer changed.
The preview reads the previous proof, prompt, schema and auth directory without the removed executable.
It shows the previous digest and the name-based digest measured at preview.

It reports the previous physical computer as unverified.

The new terms use a typed digest of Darwin's public physical computer ID.
Muninn invokes `gethostuuid` one time, with a positive wait of at maximum 50 ms.
A shorter caller deadline reduces that wait.
This limits the native resource wait, not total operating-system wait.

Muninn keeps no raw ID or computer name.
There is no second identity source if the `call` cannot supply a checked ID.

The same physical ID permits a computer-name change.
A different or unavailable physical ID stops enrollment, native setup and checked restart.
Memory bridge gates check the same approved change without a native ID `call`.
They keep the current local proposal, source and generation rules.

The installer checks the selected release's prepared source files before grant publication, in the SQL commit and before restart or committed `resume`.
The source must declare `codex-managed-host-enrollment-v1` and parse the new managed terms.
The older runner-selection marker cannot satisfy this check.
A subsequent runtime downgrade leaves the committed grant stopped for checked recovery.

Keep stable selection in the policy and `attempt`.
Keep actual checked identity and append-only activation history for each `call`.
Compatible updates leave the grant unchanged.
Use at maximum one positively proved pre-exec refresh with the same reserved `call`.

Do not automatically relaunch started or uncertain execution.

Keep the complete eligible previous queue through one finite initial capsule.
Check its immutable snapshots and `original` inputs at each authority/read gate.
Keep usual generation, source, erasure, `attempt` and budget fences.
Unsupported pending decision work refuses.

Do not cancel or recreate work to migrate it.

Use `capability` cache as disposable `evidence`.
Safe invalid content needs all isolated checks again with the `original` deadline.
Storage that fails privacy or identity checks refuses.
Write complete private metadata atomically.

Authority loss cannot reconstruct consent.

Use typed versioned JSON in current storage.
There is no DDL or store marker change.
Current copy and row fingerprints include the unchanged JSON.
Previous code cannot parse the new authority.

A committed grant stays paused after error.
Checked recovery must use compatible code and must not put back a previous archive.

Cleanup records a proved SQL commit before it pauses admission.
If that record write also has an error, the service stays stopped and the unchanged SQL `state` stays unchanged.
Admission can stay enabled while the service is stopped.
Repair the record storage fault, then run again the same command.

Do not start the service by hand or accept a changed generation as proof of the same operation.

## Consequences

Codex updates no longer need a version-specific grant.
The current procedure applies only to Apple silicon macOS.
Generic runner behavior and executable limits stay unchanged.
Codex package `bounds` are 384 MiB for each file, 512 MiB for each package, 256 inventory paths and depth eight.

Same-user compromise, auxiliary `origin` and actual billing stay unverified.
Help output proves advertised arguments, not future model behavior or full `isolation`.
Usual result validation, containment and all prior limits stay.
Private kept recovery copies keep their current limits on erasure and restoration.
